Установка программы
1. Запустите установочный файл
2. Найдите и запустите файл ArtonitRestApi_Setup_1.0.X.exe.
3. Выберите путь установки, по умолчанию программа установится в C:\ArtonitRestAPI, при необходимости измените путь и нажмите "Далее".
4. Опционально: Установка как службы
	4.1.Отметьте "Установить как службу", если требуется, нажмите "Далее".
5. Проверьте параметры установки, нажмите "Установить", после завершения нажмите "Завершить".



Настройка подключения к базе данных:
Путь к базе данных находится в файле конфигурации "C:\ArtonitRestAPI\appsettings.json"
Параметр "DatabaseConnectionString".
путь по умолчанию: "C:\\Program Files (x86)\\Cardsoft\\DuoSE\\Access\\", после папки Access необходимо вставить название файла с расширение "GDB".

Инструкция по запуску:
1. Если была произведена установка службы, то для запуска API необходимо ввести следующий адрес "http://localhost:5056/swagger/index.html"
2. Если была произведена установка без службы, то для запуска необходимо перейти в папку "C:\ArtonitRestAPI", в ней найти файл "ArtonitRESTAPI.exe" и запустить его, 
после чего ввести в строку браузера "http://localhost:5056/swagger/index.html".


REST API v2:
В версии v2 сотрудник идентифицируется по табельному номеру tabnum вместо id_pep.
Методы v1 сохранены без изменений. Описание методов v2, правила формирования tabnum
и примеры запросов находятся в файле REST_API_v2.md.

Управление организациями (версия 1.2.0):
Добавлены команды /api/v2/organizations: создание, чтение, постраничный список,
полная (PUT) и частичная (PATCH) замена полей, удаление. Полное описание, формат ошибок
и соответствие таблице ORGANIZATION — в файле docs/ORGANIZATIONS_API_v2.md.
Изменяющие команды требуют токен с ролью администратора: /login?username=ADMIN&pasword=333.
Для базы данных подготовлены миграции в docs/migrations (уникальный индекс DIVCODE
и необязательная колонка DATE_CREATE). Дымовой тест API — docs/smoke-tests/organizations.ps1.

Управление категориями доступа (версия 1.3.0):
Команды /api/v2/Access: добавление категории, удаление по ID_ACCESSNAME, постраничный
список категорий и список сотрудников (tabnum) с указанной категорией. Категории хранятся
в ACCESSNAME, связи с сотрудниками — в SS_ACCESSUSER. Полное описание и примеры —
в файле docs/ACCESS_API_v2.md, дымовой тест — docs/smoke-tests/access.ps1.

Связи организаций с категориями доступа (версия 1.4.0):
Метод GET /api/v2/organizations/{divcode}/accessnames возвращает список id_accessname,
привязанных к организации в таблице SS_ACCESSORG. Ответ — JSON-массив целых чисел
по возрастанию; если организация не найдена — 404, если связей нет — пустой массив.
Описание — в docs/ORGANIZATIONS_API_v2.md.

Сохранение категорий доступа организации (версия 1.5.0):
Метод PUT /api/v2/organizations/{divcode}/accessnames сохраняет полный набор категорий
доступа организации: тело {"accessnames":[...]}, лишние связи удаляются, недостающие
добавляются, пустой массив очищает набор. Ответ — сохранённый массив id_accessname
по возрастанию. Метод изменяющий: требуется токен с ролью администратора.
Описание — в docs/ORGANIZATIONS_API_v2.md, проверки — в docs/smoke-tests/organizations.ps1.

ФИО и категории доступа сотрудника (версия 1.6.0):
- PUT /api/v2/Person полностью заменяет ФИО сотрудника, найденного по tabnum:
  тело {"tabnum","surname","name","patronymic"}, фамилия обязательна, имя и отчество
  могут быть пустыми. Ответ — сохранённые значения.
- GET /api/v2/Person/Access?tabnum=... возвращает набор категорий доступа сотрудника
  (JSON-массив id_accessname по возрастанию, 0 — допустимая категория Check Time).
- PUT /api/v2/Person/Access сохраняет полный набор категорий доступа сотрудника:
  тело {"tabnum","accessnames":[...]}, лишние связи снимаются, недостающие выдаются,
  пустой массив очищает набор. Ответ — итоговый массив id_accessname.
Оба PUT-метода изменяющие: требуется токен с ролью администратора. Изменения
выполняются в Firebird одной транзакцией (таблицы PEOPLE и SS_ACCESSUSER), набор
категорий меняется обновлением только отличий от текущего. Подробное описание,
ограничения и примеры — в docs/PEOPLE_API_v2.md.

Статистика по сотрудникам (версия 1.7.0):
- GET /api/v2/Person/GetCount возвращает количество всех записей в таблице PEOPLE,
  количество активных (ACTIVE = 1) и неактивных (ACTIVE = 0) сотрудников:
  {"total":79,"active":79,"inactive":0}.
- GET /api/v2/Person/GetList получил необязательный параметр active: all или пусто —
  все записи, 1/true/active — только ACTIVE = 1, 0/false/inactive — только ACTIVE = 0.
  Структура ответа и пагинация не изменились, pageCount считается после фильтра.
Методы только читают данные. Подробное описание — в docs/PEOPLE_API_v2.md,
дымовой тест — docs/smoke-tests/people-stats.ps1.

Статистика по идентификаторам (версия 1.8.0):
- GET /api/v2/Identifier/GetCount возвращает количество записей таблицы CARD
  после фильтров: всего, активных (ACTIVE = 1) и неактивных (ACTIVE = 0):
  {"total":12,"active":10,"inactive":2}.
- GET /api/v2/Identifier/GetList получил фильтры tabnum, timestart, timeend,
  active, id_cardtype и createdat (плюс прежний identifire по номеру карты).
  В элементах списка добавлены timestart, timeend, active и createdat;
  пагинация и pageCount считаются после фильтров.
Для дат поддерживается дата (весь день) и дата-время (точное совпадение).
Методы только читают данные. Подробное описание — в docs/IDENTIFIERS_API_v2.md,
дымовой тест — docs/smoke-tests/identifiers-stats.ps1.
